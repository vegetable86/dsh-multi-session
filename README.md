# 多会话面板（dsh-multi-session）

在 DeepSeek Harness 里把多个会话并排看：一个独立的「多会话」主面板，格子数量不设上限，每格绑定一个已有会话，每格都是完整的原生对话（消息流 + 输入框）。所有格子不重叠地平铺，拖动分隔条就能像 tmux 那样调整相邻格子的长宽。

npm 包：`@vegataa/dsh-multi-session`

## 用法

1. 左侧边栏点「多会话」图标进入面板。
1.1 面板最上方是类似浏览器的标签栏：每个标签都是一整套独立的多会话布局（自己的格子、分隔条权重、最大化 / 最小化状态）。点标签切换，`+` 新建一个标签（打开的是一张白纸：一个空格子等你选会话，不会复制当前标签，并沿用当前的风格和密度），`×` 关闭标签（至少保留一个），双击标签可以改名，按住标签拖动可以调整它们的前后顺序；标签标题默认跟着它的第一个会话走，会话正在跑时标签上有个小绿点。
2. 首次打开自动填入最近两个会话；每格标题栏点会话名可以换一个会话（支持搜索）。
3. 标签栏右侧的「+ 添加会话格」想加多少加多少。格子不重叠地平铺：两格并排，三格是上面一整格、下面两格，四格是 2×2，更多格子按两列往下排。拖行与行之间的横分隔条，上下两行一起变高变矮；拖同一行里两格之间的竖分隔条，一边变宽另一边就变窄，和 tmux 的分屏手感一样。任何时候格子都会铺满面板、不会互相遮挡。单格可最大化 / 还原，也可关闭（至少保留一格）。标签栏右侧的「均分」把所有分隔条恢复成平均分配。
3.1 每格标题栏的「最小化」把它收成面板上方的一条标题（带运行状态点）；收起的格子不占网格空间，剩下的格子自动铺满，点标题即可展开回原来的位置。所有格子都可以收起。
3.2 每格标题栏的「在主面板打开」（箭头图标）把该格的会话交给普通对话页显示，多会话面板随之退到侧边栏；适合临时想仔细看某一段对话时用。标题栏还可以按住拖到另一个格子上：松手后两格交换各自显示的会话，格子的位置和大小不变。
4. 空格的「新建会话」按钮、以及每格选择器底部的「新建会话」，会先弹出一个工作区选择框：选好工作区后再在这一格里创建会话，整个过程都留在多会话页面，不会跳到新会话。没有工作区时才退回 Host 的默认目录。
5. 标签栏右侧的「沉浸全屏」（四个角的图标）把整个面板铺满窗口，盖住左右两栏，能多出侧栏那一整条宽度；再点一次或按 `Esc` 退出，布局原样保留。
6. 标签栏右侧的密度按钮在「紧凑 / 舒适」之间切换：紧凑是默认值，同样的窗口能多显示几行对话；舒适会把间距、按钮、标签和分隔条整体放大一档。选择随布局一起记住。
7. 第一次打开面板时，标签栏下方有一条操作提示（拖分隔条调大小、拖标题栏交换会话、标题栏箭头在主面板打开），点「知道了」收起；标签栏右侧的 `?` 随时能再叫出来。图标按钮悬停会立即显示名称，标题栏左侧的六点手柄表示这一格可以拖动。
8. 布局、每格绑定的会话、最大化 / 最小化 / 全屏 / 密度状态都会自动记住，刷新或重启后恢复；会话不存在时那一格显示「不可用」，可以重新选择。
9. 选择器默认不列子代理会话，也不列空白会话（当前格自己绑定的空白会话除外）。
10. 界面更安静：标签和所有操作并在标签栏一行里，格子标题栏的按钮只在悬停或该格为活动格时出现；增删格子、最大化、最小化、切标签、弹出对话框都带 140–320ms 的过渡。系统开启「减少动态效果」时，这些动画会自动关掉。

11. 后台标签只保留布局轮廓，不再保留活的对话：切回来会重新连接会话（滚动位置不保留）。这是为了保证同一个会话在任一时刻只有一个输入框在跑——两个输入框同时挂在一个会话上会互相抢草稿，导致按回车发不出去。
12. 同一个会话被放进两个格子时，第二个格子会提示「已在另一格显示」，不会出现两套输入框。
13. 标签栏右侧的小字 X.Y.Z 是当前加载的构建版本，反馈问题时报这个版本号最省事。
14. 格子里的对话也换上了 Claude 风格的暖色主题：面板在自己的根节点上重设 DSH 的主题变量（`--dsw-alias-*` 与 `--dsw-font-markdown-*`），对话区、代码块、滚动条、边框会跟着一起变，正文改用偏暖的衬线字体；这套配色只作用于多会话面板，其他页面不受影响。
15. 标签栏右侧的调色板按钮可以换风格：跟随平台（默认）、Claude 浅色、Claude 深色、ChatGPT、Terminal 绿、Terminal 琥珀。选择会存进布局，刷新后保留，所有标签共用一套皮肤。
16. 空白会话页面里的「工作区」选择器也留在本页：在多会话里挑一个新工作区，会直接在那个空白的格子里开一个新会话，不会跳回单个对话页。
17. 每个绑定了会话的格子，标题栏里有一个「改动」按钮：点开会在格子右侧滑出抽屉，列出这一轮改过的文件（路径、增删行数），点文件可以看逐行 diff，也能用「在编辑器中打开」直接跳到外部编辑器。抽屉里只读，不会改到工作区。
18. 对话里出现的文件链接也留在格子里：点文件名会在同一格右侧滑出只读预览（等宽字体、最多 4000 行），不再弹「sidebarRight: no session surface is mounted」。

## 实现要点

- 只注册一个 `main` 面板（key `multisession`）和一个 `sidebar.panellist` 图标，普通对话页完全不受影响。
- 每格通过 `<SessionProvider session={reference}>` 显式绑定会话，引用由 `sessions.retain(...)` 获取、卸载时 `release()`。
- 格子内部用官方 `conversation.content` 工厂槽（`variant: 'embedded'`）渲染，得到的是原生对话组件，不是自绘的聊天界面。
- 每格包两层错误边界：格子内的渲染异常会在 0.6s / 1.2s 后自动重建两次，仍失败才显示错误卡片（可手动「重试」）；整个面板崩了还有一层兜底，可以一键清掉布局重置。
- `conversation.content` 是 Harness 的内部工厂槽，签名变了会抛错：每格对这次调用做了捕获，失败时只显示「此视图暂不可用」+ 重试，不会把整个面板打空。
- 「新建会话」自己问工作区，然后直接 `sessions.create({ workspaceId })`；不走 `uiWorkspace.openWorkspace`——后者在 hero 工作区选择器里会 `layout.selectPanel(null)`，把主面板切回单个会话，这正是新建后跳走的原因。
- 格子的外壳用 `React.memo` 包起来：拖动分隔条时只有父级容器重算样式，各格的对话组件不会跟着重渲染。
- 最大化改为 CSS 覆盖层（其余格子 `visibility: hidden` 但保持挂载），切换最大化不会重挂载对话，滚动位置和正在流式的回复都保留。
- 沉浸全屏不是新窗口，也不是新面板：根节点切到 `position: fixed; inset: 0`，一层 `z-index` 盖住三栏框架，面板里的会话组件完全不用重挂载；`Esc` 先退最大化、再退全屏。顶部留出 Windows 标题栏的高度，避免盖住窗口拖动区。
- 「在主面板打开」调用平台的 `uiWorkspace.openSession(sessionId)`；它会把该会话交给当前主面板并切换到单个对话，属于宿主既有的导航入口，插件不自己造一套。
- 风格是一张注册表（`THEMES`）：每套皮肤只声明一份 CSS 变量映射（面板自己的 `--ms-*` 加上对话区读取的 `--dsw-alias-*` 与字体 token），切换时把变量写在面板根节点上。因为变量沿子树继承，原生对话会跟着换色，但不会影响面板之外的页面；「跟随平台」这套故意什么也不覆盖。
- 交换会话走 HTML5 拖放，MIME 用自定义的 `text/x-multisession-pane`，只在面板内部认；拖拽过程中不改 DOM 结构，松手时只交换两个格子的 `sessionId`，所以对话视图和滚动位置都还在原来的格子实例里。
- 格子按「行 → 列」两级权重存储：每行的 `rowWeights` 决定高度，每行内两格的 `colWeights` 决定宽度；拖动分隔条只改这两级权重，所以相邻格子永远互补、整块面板始终铺满。最小化是每个格子的 `minimized` 标志：收起后该格不再参与网格计算（行里只剩一格就独占整行），但它在 `rows` 里的位置保留着，展开即回原位。
- 标签栏是「多套布局」而不是「多套面板」：v8 的存储是一份 `{ tabs, activeTabId, immersive, density, theme }`，每个 tab 里放的正是原来那套 `panes / rows / rowWeights / colWeights / maximizedId`。切标签只是换 `activeTabId`，面板本身不重建；旧版本（v1–v7）的布局会原样升级，不会丢。
- 最近访问的 3 个标签会保持挂载（`MAX_MOUNTED_TABS`）：切回来时滚动位置、输入框草稿和正在流式输出的内容都还在；超出的标签整块卸载，但会话本身在后台继续跑。
- 密度不是两套样式表：`METRICS` 里放紧凑 / 舒适两档的尺寸，组件通过 `DensityContext` 取当前这档，拖动计算（`beginSplitDrag` 的可用像素、最小格宽高）也跟着同一份数字走，避免尺寸和命中区各算各的。
- 分隔条只在视觉上是 6px / 10px 的细线：外层是命中区，内层 `span` 才是那条线，悬停只改内层颜色和透明度，不改布局，所以拖起来不会抖。
- 动画只用 Web Animations API（animateIn 统一曲线）和 CSS 过渡，不注入额外样式表；每次调用都先看 prefers-reduced-motion。
- 改动抽屉读的是平台自己的接口（`api/changes.summary` 与 `api/changes.diff`），坐标从对话的 chat 视图时间线里取：每个 turn 的 `deliverables.changes.seq` 指向那一轮的改动集。插件不缓存、不重算 diff，只是把同一份数据搬进格子里；「在编辑器中打开」走 `api/changes.open`，和平台右侧栏的改动面板是同一个后端。
- 对话里的文件链接是平台右栏的资源地址（`dsh-resource://file/session/<id>/<path>`），而右栏命令要求「屏幕上的会话」有已采纳的 session surface；多会话是 root 作用域面板，没有这个 surface，所以点链接会报 `sidebarRight: no session surface is mounted`。插件在 `apply` 里包了 `ctx.sidebarRight.openResource`：地址对应的会话正在某个格子里时，就地把文件预览开在那个格子（正文用 `remote.workspaceFiles.read` 读），其余地址原样交回平台。读取正文要用 `remote.workspaceFiles`，它和 `remote` 一样必须写进客户端 `inject` 列表——Cordis 不允许访问未声明的子服务（否则会报 `cannot get property "remote.workspaceFiles" without inject`）。
- 主题不是改平台：多会话面板在根节点注入一组 `--dsw-alias-*` 变量（`themeVars`），ui-conversation / ui-chat 的 28 个样式模块都用这些 token，变量沿子树继承，所以格子里的原生对话会被一起重新着色；插件自己的标签栏、卡片、强调条则用 `--ms-*` 变量，两者共用同一份 `THEME` 色板。
- 标签拖动排序走 HTML5 拖放（自定义类型 `text/x-multisession-tab`），松手时只重排 `board.tabs` 数组，`activeTabId` 不变、布局不重建；拖到标签条空白处则移到最末。落点只按左右半区判断插到目标前还是后，不额外算几何。
- 空白会话的 hero 工作区选择器来自平台，本身走 `uiWorkspace.openWorkspace` → `replaceMain(..., 'reveal')` → `layout.selectPanel(null)`，因此会切走主面板。插件在 `apply` 里给 `openWorkspace` 包了一层：面板挂载期间、且这次点击确实发生在面板内（6 秒内的指针交互）、当前又有空白格时，把「在那个工作区建会话」接过来，直接 `sessions.create({ workspaceId })` 绑到那个格子；其他来源的调用原样交回宿主。

## 开发

纯手写客户端 bundle，无需构建步骤。`client.js` 直接就是 `window.__ModuleLoader__.load(...)` 包。

```powershell
npm test   # 注册形态冒烟 + jsdom 渲染冒烟
```

